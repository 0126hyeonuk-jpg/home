# 찐말랑 하우스

SH·LH·청년안심주택 3개 기관 각각의 신혼부부 대상 입주자모집공고를 최신순 리스트로 한 페이지에서 확인하는 웹페이지입니다. 기관마다 **오늘 기준 최근 2개월 이내** 게시된 공고를 모두 보여주며(상시모집/수시모집 항목은 예외), 1차/2차 같은 일괄공고 외에 개별 단지 공고도 함께 표시됩니다. 2개월 내 신규 공고가 없는 기관은 그 사실을 그대로 안내합니다.

**페이지: https://0126hyeonuk-jpg.github.io/home/** (GitHub Pages 활성화 후 접속 가능 — 아래 "배포" 참고)

> 이전에는 Claude Artifact로 운영했지만, "실제 웹페이지 + 버튼으로 바로 갱신" 요청에 맞춰 **GitHub Pages(정적 사이트) + GitHub Actions(스크래퍼)** 구조로 옮겼습니다. Artifact 버전은 더 이상 자동 갱신되지 않습니다.

- 보증금·임대료 상한: 없음

- 기간: 오늘 기준 최근 2개월 이내 게시된 공고만 (상시모집/수시모집 항목은 예외)

## 구조

```
data/live.json        실제 데이터(공고 목록·캘린더 이벤트) — 이 파일이 진실의 원천
templates/page.html   디자인·CSS·인터랙션 스크립트가 담긴 뼈대(플레이스홀더 포함)
scripts/scrape.py      SH·LH·청년안심주택 목록 페이지를 실제로 긁어와 live.json에 병합
scripts/build.py       live.json + page.html → docs/index.html 생성
docs/index.html        GitHub Pages가 실제로 서빙하는 완성된 페이지 (생성물, 직접 수정 X)
.github/workflows/update.yml   스케줄 + 수동 실행 워크플로
```

## 배포 (GitHub Pages) — 최초 1회 설정 필요

이 저장소 Settings → Pages에서 **Source: Deploy from a branch**, **Branch: `claude/subscription-info-webpage-mynp6j` / `/docs`** 로 지정하고 저장하면 위 페이지 URL이 활성화됩니다(저장소 소유자만 가능한 설정이라 Claude가 직접 켤 수 없어요).

## 자동 갱신 · 지금 바로 갱신하기

**`.github/workflows/update.yml`**이 매일 오전 10시(KST, cron `0 1 * * *` UTC)에 GitHub의 서버에서 실행되어, `scripts/scrape.py`로 3개 사이트 목록 페이지를 **실제로 요청해서** 최신 공고를 가져오고, `scripts/build.py`로 페이지를 다시 만든 뒤 변경이 있으면 자동 커밋·푸시합니다.

**지금 바로 확인하고 싶을 때**: 저장소의 [Actions → 찐말랑 하우스 자동 갱신](https://github.com/0126hyeonuk-jpg/home/actions/workflows/update.yml) 탭에서 **Run workflow** 버튼을 누르면 스케줄과 상관없이 즉시 같은 작업이 실행됩니다(로그인한 저장소 협업자만 가능 — GitHub 특성상 공개 페이지의 버튼이 남의 저장소 작업을 실행할 순 없어서, 실행 버튼은 GitHub Actions 화면에 있습니다).

- 이 스크래퍼는 GitHub Actions 러너(실제 인터넷 접근 가능)에서 돌아가므로, Claude 세션 안에서는 막혀있던 3개 사이트에 직접 접속해 목록을 가져옵니다. 다만 사이트 구조가 바뀌거나 자바스크립트 렌더링에 의존하는 경우 파싱이 실패할 수 있는데, 이때는 기존 데이터를 그대로 유지하고 실패 사실만 기록합니다(자동으로 잘못된 데이터를 지어내지 않습니다).
- 새로 발견된 공고는 지역·면적·신혼부부 해당 여부를 "확인 필요"로 표시된 채 추가되며, 정밀한 판정은 Claude와의 대화(WebSearch/PDF 분석)로 보완해야 합니다.
- `data-verified="true"`(PDF로 직접 확인한 공고)는 스크래퍼가 절대 덮어쓰지 않습니다 — 날짜·상태만 갱신 대상에서도 제외됩니다.

이전에는 이 저장소 밖의 Cowork 루틴(WebSearch 기반)이 Claude Artifact 페이지를 갱신했지만, 이제 위 GitHub Actions 워크플로가 이 저장소 안에서 실제 스크래핑으로 이 정적 페이지를 갱신합니다. 기존 루틴은 중복 유지보수를 막기 위해 비활성화했습니다.

## 인터랙션

각 공고를 클릭하면 외부 사이트로 바로 이동하지 않고, 페이지 안에서 팝업(모달)으로 "PDF·공고문 분석 인사이트"가 뜹니다. 이 텍스트는 `data/live.json`의 각 공고 `insight` 필드에서 나와 `scripts/build.py`가 `<script>`의 `INSIGHTS` 객체로 생성합니다. 팝업 안의 "원문 공고 열기" 버튼을 눌러야 실제 사이트로 이동합니다.

## 청약신청일 캘린더 · D-day

페이지 상단에 접수기간·청약시작일이 확인된 공고만 월별 캘린더로 보여줍니다(데이터는 `data/live.json`의 `events` 배열, 오늘 날짜는 `today` 필드 — 빌드 시 각각 `EVENTS`/`TODAY`로 주입됩니다). 캘린더 위에는 같은 데이터로 자동 계산되는 D-day 칩 스트립(`renderDdayStrip`)이 있어 "D-2", "접수중", "마감"을 한눈에 볼 수 있습니다. 날짜 막대나 D-day 칩을 클릭해도 같은 인사이트 팝업이 뜹니다. 접수 일정이 불확실한 공고는 캘린더에 억지로 넣지 않고 `undated_note` 필드에 안내만 남깁니다(D-day는 EVENTS/TODAY에서 자동 계산되므로 별도 데이터가 없습니다). `scripts/scrape.py`는 지금 캘린더 이벤트를 자동으로 만들지 않으므로, 새 공고의 접수일정은 사람이(또는 Claude와의 대화로) `events`에 추가해야 합니다.

## 신청 준비서류 체크리스트

페이지 하단에 신혼부부 청약에 공통적으로 자주 쓰이는 서류 목록(신분증, 등본, 혼인관계증명서, 소득·자산 증빙 등)을 접이식 체크리스트로 넣었습니다. 체크 상태는 보는 사람의 브라우저(localStorage)에만 저장되며, 공고 데이터와 무관한 고정 콘텐츠라 자동 갱신 루틴은 이 섹션을 건드리지 않습니다.

## 탐색 편의 (툴바 · 필터 · 맨 위로)

헤더 아래 상단 툴바가 스크롤해도 화면에 고정됩니다. 왼쪽 "청년안심주택/LH청약플러스/SH 인터넷청약시스템" 버튼을 누르면 해당 섹션으로 부드럽게 스크롤 이동하고, 오른쪽 "전체/접수 가능만/📄 PDF 확인만" 3단 필터로 접수마감(`status-badge closed`)이거나 PDF로 검증 안 된 공고를 숨길 수 있습니다(개수도 함께 표시). 필터 결과 어떤 섹션에 표시할 공고가 하나도 없으면 안내 문구가 뜹니다. 페이지를 일정 이상 내리면 오른쪽 아래 "맨 위로" 버튼이 나타납니다. 자동 갱신 루틴은 이 구조(id, 클래스, 렌더링/필터 함수)를 건드리지 않고 데이터만 갱신하도록 지시해뒀습니다.

## PDF 확인 표시

사용자가 대화에 공고문 PDF를 직접 올려서 Claude가 실제로 읽고 검증한 공고에는 `data/live.json`에서 `"verified": true`가 붙고, 페이지에는 `data-verified="true"` 속성과 `📄 PDF 확인됨` pill로 표시됩니다(현재 SH 미리내집 1차, SH 제8차 장기전세주택2(미리내집) 2건). `scripts/scrape.py`는 이 표시가 붙은 공고를 절대 덮어쓰거나 삭제하지 않습니다. 실제로 제8차 장기전세주택2 건은 예전 WebSearch 기반 자동 갱신이 잘못 가져온 정보(엉뚱한 단지명·세대수)를 PDF 원문 확인 후 정정한 사례였습니다. 앞으로 새 PDF를 Claude와의 대화에 올리면 `data/live.json`의 해당 항목을 수정해 `verified: true`로 표시하고 커밋하면 됩니다.

## 참고

- 이 페이지에 표시된 조건 중 "확인 필요"로 표시된 항목은 공개된 정보만으로 확정하지 못한 값이며, 신청 전 반드시 각 기관의 공고문 원문을 확인해야 합니다.
- 접수기간이 지난 공고는 다음 차수가 게시될 때까지 최근 공고로 표시될 수 있습니다.
